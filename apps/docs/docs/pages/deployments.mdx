# Deployments

The protocol lives on **Base Sepolia** and a **local anvil** chain. There is no
Base mainnet deployment yet.

The SDK never needs these hardcoded — `CHAINS`, `DEFAULT_CHAIN` and
`isDeployedOn(chainId)` from `@0xslots/contracts` are all derived from the
address maps below, so the set of usable chains is exactly the set that has a
`SlotFactory` recorded.

## Base Sepolia — 84532

## Local anvil — 31337

`pnpm dev:local` at the repo root starts a chain, deploys the protocol and runs
an indexer against it. The addresses are **pinned** — they survive edits to the
Solidity, which a plain CREATE2 would not, since CREATE2 hashes the init code and
so moves whenever the contract changes. See `LocalBootstrap.sol`.

| Contract | Address |
|---|---|
| SlotFactory | `0x15381307cb597d266646df5De8675D7d0e74520d` |
| OfferBook | `0xA694f81Bd45229C7279C6BD7a174BAb70f494CA3` |
| MinimumTenureHook | `0x3b326f66EF59FE6E3724d4FCd23E6F024f0c91f9` |
| MinimumTenureHookFactory | `0xa513E6E4b8f2a923D98304ec87F64353C4D5C853` |
| AdLand (hook) | `0x295016ED87CDef4DbE80B3BB74c5E23e326199c3` |
| SlotsTestToken | `0x97B3FA892E0C220f66B2F665553aF1192B63dB12` |

`CHAINS` filters anvil out unless `NODE_ENV === "development"`. Bundlers inline
`NODE_ENV`, so a production build drops the entry at compile time rather than
shipping a chain option pointing at nobody's localhost. The address tables
themselves are unconditional — they are only data, and a consumer that knows it
wants the local factory can still ask for it by id.

<Callout type="warning">
Use the SlotFactory listed here and nothing else. A slot created through a
factory the indexer does not watch is **invisible to every consumer** — and it
fails silently, because the transaction itself succeeds.
</Callout>

## Naming a hook

A slot stores its hook as a bare address. To turn that back into something a
person recognises, `@0xslots/contracts` ships a small catalogue of the hooks it
can name, per chain:

```ts
import { knownHooks, findKnownHook } from "@0xslots/contracts";

const known = findKnownHook(84532, slot.hook);
// known?.name — e.g. "AdLand — publish a creative", or undefined for a hook
//                this client does not recognise
```

A hook appears in `knownHooks` on exactly the chains it is deployed to, because
the entries are derived from the deployment records — there is no per-chain edit
to keep in sync. An address the catalogue does not know reads back as `undefined`
rather than a guess; that is the honest answer for a hook anyone can deploy.

For a hook minted at a CREATE2 address — the `MinimumTenureHook` family — the
factory's `predict()` and `verify()` are the authoritative check that an address
is a genuine instance of that kind. See
[Hooks reference](/reference/hooks#verification).

## ABIs

```ts
import {
  slotAbi,
  slotFactoryAbi,
  offerBookAbi,
  minimumTenureHookAbi,
  minimumTenureHookFactoryAbi,
  compositeHookAbi,
  adLandAbi,
} from "@0xslots/contracts";
```

Addresses are exported as per-chain maps, so you rarely need to hardcode one:

```ts
import { slotFactoryAddress, offerBookAddress } from "@0xslots/contracts";

const factory = slotFactoryAddress[84532];
```
