# OfferBook

Standing bids on a slot, and the fill that settles them. Anyone may post "I will
take that slot at this price"; the occupant reads the best one and accepts it.

The book is **periphery**. The core knows nothing about it — deploy another and
it competes.

## Why the book performs the fill

A consensual sale is two calls the core already has, in one transaction:

```solidity
slot.selfAssess(price)                 // the occupant's price, restated
slot.buy(bidder, price, deposit, max)  // the ordinary market path
```

`buy` already refunds the outgoing occupant their deposit plus the price. So
there is one seating path, and the slot's module gets its say — on the reprice
and on the seating — like on any other buy.

## Posting a bid

```solidity
function offer(address slot, uint256 price, uint256 deposit, uint64 expiry)
    external returns (uint256 id);

function cancel(address slot, uint256 id) external;   // bidder only
```

One transaction, and no signature: `offer` is a call **from** the bidder, so
posting is the consent. One offer per bidder per slot — posting again updates
your standing one under the same id.

Bids are **allowance-backed, not escrowed**. The book pulls the payment during
the fill and spends it in the same transaction; if the funds are gone when the
occupant accepts, the transfer reverts and the seller loses gas and nothing else.

<Callout type="warning">
Approve the **book**, not the slot, for `price + deposit` plus any debt you owe
that slot. `buy` charges `msg.sender`, and on a fill that is the book.
</Callout>

## Accepting a bid

```solidity
function acceptOffer(address slot, uint256 id, uint256 minPrice) external;   // occupant only
```

`selfAssess` is `onlyOccupantOrOperator`, so the occupant makes the book their
operator first:

```solidity
slot.setOperator(book, true);
book.acceptOffer(slot, id, minPrice);
```

`minPrice` is the price the seller reviewed. A bidder edits an offer in place
under the same id, so without it a bidder could lower their price between the
seller reading the board and the fill landing.

The operator grant is keyed by tenure on the slot's side, so it lapses by itself
when the slot changes hands.

<Callout type="warning">
It is a real power — repricing to dust would let anyone take the slot cheaply.
Which is why **the book is not upgradeable** and has no admin or owner: the code
an occupant approved is the code that runs. `acceptOffer` is the only function
that touches a slot, it reprices only to a live offer's price, and it reverts
unless `msg.sender` is the occupant.
</Callout>

### Errors worth handling

| Error | Meaning |
|---|---|
| `NotOccupant` | only the sitting occupant may accept a bid on their slot |
| `NotOperator` | the book has not been granted `setOperator` for this tenure |
| `OfferNotLive` | cancelled, expired, filled, unfunded, or the bidder is the occupant |
| `PriceBelowMinimum(price, minPrice)` | the offer was lowered after the seller read it |
| `NativeSlotNotSupported` | native slots cannot be filled — see below |
| `TopUpRequired(shortfall)` | accepting a higher bid raises the escrow floor above what the seller holds |

`TopUpRequired` is the one that surprises people. Raising the declared price
raises the minimum escrow with it, and `selfAssess` enforces that floor against
the deposit **already in the slot** — the seller's, not the bidder's. Top up by
the reported shortfall and retry; it comes straight back in the sale proceeds.

<Callout type="info">
**ERC-20 only.** The occupant sends the transaction, so there is no way to reach
the bidder's ETH.
</Callout>

## Reading the board

```solidity
function board(address slot) external view
    returns (Offer[] memory offers, bool[] memory live);

function best(address slot) external view
    returns (bool found, uint256 id, Offer memory offer);

function liveCount(address slot) external view returns (uint256);
function offerCount(address slot) external view returns (uint256);
function isLive(address slot, uint256 id) external view returns (bool);
function isFundable(address slot, uint256 id) external view returns (bool);
function offerOf(address slot, address bidder) external view
    returns (bool has, uint256 id, Offer memory offer);
function offerAt(address slot, uint256 id) external view returns (Offer memory);
function offers(address slot) external view returns (Offer[] memory);
```

`board` returns the list **and** the contract's own per-entry liveness verdict in
one call, which is why it is preferred over `offers` plus N `isLive` reads.

<Callout type="warning">
Count `liveCount`, never `offerCount` — the latter counts every row ever posted,
cancelled and filled included.

Filter on `isLive`, never `isFundable`. `isFundable` asks only whether the bidder
could still pay, and a **filled** offer goes on answering yes.
</Callout>

## Events

```solidity
event Offered(address indexed slot, address indexed bidder, uint256 indexed id,
              uint256 price, uint256 deposit, uint64 expiry);
event Cancelled(address indexed slot, address indexed bidder, uint256 indexed id);
event Filled(address indexed slot, address indexed bidder, uint256 indexed id,
             address seller, uint256 price, uint256 deposit);
```

`Filled` is the seller's side of a sale. The slot emits `Bought` in the same
transaction, so occupancy history is complete from the slot alone.

<Callout type="info">
The book is not indexed yet, so `Filled` is not queryable — see
[Indexer](/indexer).
</Callout>
