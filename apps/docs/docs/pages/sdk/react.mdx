# React Hooks

Wagmi-wired hooks from `@0xslots/sdk/react`. Requires `wagmi`, `viem`, and `@tanstack/react-query` as peer dependencies.

## `useSlotsClient`

Creates a memoized `SlotsClient` from wagmi's public and wallet clients.

```tsx
import { useSlotsClient } from "@0xslots/sdk/react";

const client = useSlotsClient();                 // connected chain
const client = useSlotsClient(SlotsChain.BASE);  // override chain
```

The hook takes **one** parameter. The old second argument was a subgraph API
key; the indexer serves GraphQL unauthenticated, and passing the key through
`NEXT_PUBLIC_*` published a credential to every visitor in exchange for nothing.
It resolves the factory address from the chain and throws if there is none.

For a client against a non-default endpoint — a local indexer, or your own
deployment behind auth — construct `SlotsClient` directly and memoize it
yourself; the hook always uses `DEFAULT_API_URL`.

## `useSlotAction`

Unified write executor with transaction lifecycle tracking.

```tsx
import { useSlotAction } from "@0xslots/sdk/react";

const {
  createSlot,                                  // factory
  buy, release, liquidate,                     // occupancy
  selfAssess, topUp, withdraw, setOperator,    // holding
  collect, claim,                              // money out
  proposeTerms, cancelTerms, manageTerms,      // manager
  exec,          // generic executor
  preflight,     // dry-run a call
  busy,          // isPending || isConfirming
  isPending,     // wallet interaction in progress
  isConfirming,  // waiting for on-chain confirmation
  isSuccess,
  activeAction,  // label of current action
} = useSlotAction({
  onSuccess: (label, hash) => console.log(`${label}: ${hash}`),
  onError: (label, error) => console.error(`${label}: ${error}`),
});
```

`sell`, `makeSellOrder`, `signSellOrder` and `cancelSellOrder` are gone with
`Slot.sell`. A consensual sale is `setOperator(book, true)` once per tenure, then
`book.acceptOffer(slot, id)` — see [Selling into an offer](/sdk/client).

`proposeTerms(slot, { taxBps?, hook? })` queues the tax rate, the hook, or
both; `cancelTerms(slot, cancelTax?, cancelHook?)` retracts them, one
dimension or both. There is no separate call per dimension — a slot has two
mutable terms, tax and hook, and they move through the same pair of functions.

## Reading a slot

There is no read hook. `@0xslots/sdk/react` ships exactly two — `useSlotsClient`
and `useSlotAction` — and reads go through the client, which returns plain
promises you can hand to whatever query library the app already uses.

```tsx
import { useQuery } from "@tanstack/react-query";
import { useSlotsClient } from "@0xslots/sdk/react";

function useSlot(address: `0x${string}`) {
  const client = useSlotsClient();
  return useQuery({
    queryKey: ["slot", address],
    queryFn: () => client.slotState(address),
  });
}
```

`slotState` returns occupancy, price, deposit, tax owed, the terms, and
`hookFlags` — the hook declaration this slot snapshotted — in one call. For many
slots, call it per address and let the query client dedupe; the client batches
the underlying reads.
